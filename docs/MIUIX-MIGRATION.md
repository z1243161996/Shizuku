There is **no** `MiuixBackdrop`/`rememberMiuixBackdrop`/`Surface` provider composable: miuix-glass samples a `Backdrop` you create with `rememberLayerBackdrop()` + `Modifier.layerBackdrop(...)`. Without one, every glass component falls back to its flat `containerColor`.

## 3. THEME PLUMBING — exact wrap

Light/dark is selected by `ThemeController.currentColors()`: `System` → `isDark ?: isSystemInDarkTheme()` picks `darkColors`/`lightColors`; `Light`/`Dark` force; `Monet*` derives from `keyColor` (or platform dynamic colors). The app should create one controller in the Activity and pass it down.

What the app must wrap (replaces `GlassActivity.setGlassContent`): flat pages need only `MiuixTheme`; glass pages add the layer-backdrop box and put glass surfaces + dialogs OUTSIDE the marked box.

```kotlin
// M/app/AppActivity.kt or new MiuixActivity base:
setContent {
    MiuixTheme(ThemeController()) {                        // controller persisted in the Activity/ViewModel
        val backdrop = rememberLayerBackdrop()
        Box(Modifier.fillMaxSize().layerBackdrop(backdrop)) {   // page content IS recorded and drawn
            Scaffold(                                        // or GlassTopAppBar + content
                topBar = { TopAppBar(title = "...", navigationIcon = { IconButton({}) { Icon(...) } }) },
            ) { padding -> HomeScreen(backdrop, padding) }
        }
        GlassDialog(onDismissRequest = {}, show = showAbout, backdrop = backdrop, title = "...") { /* content */ }
        GlassBottomSheet(onDismissRequest = {}, show = showSheet, backdrop = backdrop, title = "...") { /* content */ }
    }
}
```
Rules: (1) `Modifier.layerBackdrop` must wrap the page that the glass samples — glass modifiers (`Modifier.glass`/`glassPanel`, `GlassTopAppBar`, `GlassIconButton`) must be outside that marked subtree or they create a sampling cycle. (2) Dialogs/sheets receive the same `backdrop` and sit outside the box. (3) For fully flat screens (migration default), omit the backdrop box and use plain `TopAppBar`+`Card`+`OverlayDialog`. (4) StaticGlass view dialogs are independent of this and get deleted with the Kyant UI.

## 5. RISK LIST

1. **0.9.5-beta01 is the only published miuix version and is marked experimental** (group `top.yukonga.miuix.kmp`, maven-central). No API-stability guarantee; pin the version, do not auto-upgrade.
2. **Compose version skew.** miuix-ui requires `org.jetbrains.compose.foundation:foundation:1.12.2`, `org.jetbrains.compose.material3:material3-window-size-class:1.12.0-alpha03`, `androidx.navigationevent:navigationevent-compose:1.2.0`, `com.materialkolor:material-color-utilities:6.0.0` (module metadata), while the app declares androidx compose `1.11.1` + material3 `1.5.0-alpha18` (`manager/build.gradle:161-190`). Gradle will resolve androidx-compose to 1.12.x — plan a Compose/BOM bump with this migration.
3. **Runtime shaders need API 33.** `material/androidMain/.../RuntimeShader.android.kt:18`: `actual fun isRuntimeShaderSupported(): Boolean = Build.VERSION.SDK_INT >= Build.VERSION_CODES.TIRAMISU`. minSdk is 24, so on 24-32 every `Modifier.glass`/`glassPanel`/`GlassTopAppBar`/`GlassDialog` falls back to flat `containerColor`/fallback — always pass a fallback and test both paths.
4. **Glass sampling cycle.** `Modifier.glass` must be outside the `layerBackdrop`-marked subtree (Glass.kt KDoc). Getting this wrong is a runtime black/blank surface, not a compile error.
5. **Backdrop is coordinates-dependent** (`LayerBackdrop.isCoordinatesDependent = true`): `Modifier.layerBackdrop` must be attached (onGloballyPositioned) before any glass samples it; glass inside the marked subtree has no valid coordinates.
6. **Theme must be supplyable outside an Activity** for Previews/tests: `MiuixTheme(colors = ..., textStyles = ...)` overload exists, but the `Monet*` paths call platform dynamic-color APIs — avoid those in non-Android contexts.
7. **MaterialAlertDialog + StaticGlass removal breaks v2 flows**: rows 6-11/19-22 are XML/view dialogs; if they are rewritten to Compose they must preserve Shizuku IPC result dispatch (`RequestPermissionActivity` sets `Shizuku.dispatchPermissionConfirmationResult` on button click).
8. **BottomSheetDialog (AutomationViewHolder:102)** is not Compose; converting it to `OverlayBottomSheet` changes its hosting — it currently lives in a RecyclerView holder, so move the trigger/state up to `HomeScreen`.
9. **`Scaffold` default `popupHost = { MiuixPopupHost() }`** — any popup/dropdown used must render inside a miuix Scaffold (or provide the host); don't mix Material3 popups into a miuix Scaffold.
10. **miuix-icons / miuix-nav / miuix-preference are not yet dependencies** — `manager/build.gradle:192` only has miuix-glass; add `top.yukonga.miuix.kmp:miuix-preference` and `miuix-icons` explicitly (miuix-glass does not pull preference/icons).
